# 用户手册规划

> 这是写手册期间的工作文件，不是给用户看的。正文全部写完后，把「截图清单」和「维护规则」移到 `docs/agents/user-guide.md`，然后删除本文件。

## 目标与读者

- 读者：普通 macOS 用户，不是开发者。
- 产出：
  - 改版后的 `README.md`：用户首页。
  - `docs/guide/`：用户手册，按 Diátaxis 分四类。
  - `CONTRIBUTING.md`：放从 README 迁出的开发、打包、发布内容。
- 全部用中文。

## 已定的约定

### 内容边界

- 不出现 ADR 编号、类名、实现细节和 `config.toml` 字段名。`config.toml` 只在「Mochi 存放的数据」和「卸载」两页以文件路径的形式出现。
- 界面名称一律以代码里的 UI 文案为准，以 `macos/Sources/Mochi/` 和 `macos/Sources/MochiCore/` 里的中文字符串为唯一依据。写之前先 `grep`，不凭记忆。
- 安装步骤（含首次打开被系统拦下后怎么放行）只写在 README 一处，手册里需要时链接过去。
- 现有 README 的 FAQ 迁进 `how-to/troubleshooting.md`（按症状组织），升级相关的内容同时进 `how-to/upgrade.md`。卸载迁进 `how-to/uninstall.md`。
- 自动播放、最小字体、HTTP 警告、网页开发者功能不单独写操作页，写进设置参考。

### 写作风格

- 第二人称「你」。
- 按键写符号，每页第一次出现时补全称：「⌥（Option）」「右 ⌥（右侧的 Option 键）」「⌘（Command）」「⇧（Shift）」「⌃（Control）」。
- 界面元素用「」括起来，写全路径：「设置 › 幽灵模式 › 视频控制」。
- 有两个同名的「辅助功能」，必须写清楚是哪一个：
  - 「设置 › 高级 › 辅助功能」：字体大小。
  - 「系统设置 › 隐私与安全性 › 辅助功能」：系统权限。

### 版本标注

只在手册首页写一句「本手册对照 Mochi 0.3 编写」，每次发版时核对一遍，各页正文不标版本。

### 术语对照

右列是文档用语，以界面文案为准；界面里没出现的，由文档自定。`reference/glossary.md` 只放右列和一句解释，不出现英文内部名。

| 内部术语 | 文档用语 | 依据 |
|---|---|---|
| Widget | 窗口 / Mochi 窗口 | 托盘「打开窗口」「隐藏窗口」 |
| Normal Mode | 普通模式 | 项目约定 |
| Ghost Mode | 幽灵模式 | 设置面板名、托盘 |
| Hidden | 隐藏窗口；第一次出现时补一句「相当于老板键」 | 热键名、托盘 |
| Snap | 吸附屏幕边缘 | 「拖动时吸附屏幕边缘」 |
| Mouse Passthrough | 鼠标穿透 / 点击会穿过窗口 | 设置说明 |
| Video Control | 视频控制 | 设置分组名 |
| Hotkey Forwarding / 映射 | 热键传递 / 映射 | 设置分组名、「添加映射」 |
| Trigger Key | 触发键：轻按 / 连按两次 / 组合键 | 设置 |
| Popup Window | 登录小窗（文档自定） | 界面里「弹出式窗口」那项设置管的是网页未经点击自行弹出的窗口，跟登录小窗是两回事，不能混用 |
| Script Injection | 脚本：官方内置适配脚本 / 自定义脚本 / 自定义样式表 | 脚本面板 |
| Page Permission | 网页权限 | 界面 |
| System Permission | 系统权限；具体写系统设置里的名字（辅助功能、摄像头、麦克风、文件和文件夹） | 界面 |
| Website Data | 网站数据 | 界面 |
| History / Bookmark | 历史记录 / 书签 | 界面 |
| Address Suggestions | 地址栏建议 | 无障碍标签「地址栏建议」 |

### 截图规则

- 只用 `screencapture -l<windowID>` 按窗口 ID 截图，**禁止全屏 `-x` 和区域 `-R`**。做法见 [docs/agents/macos-ui-verification.md](../agents/macos-ui-verification.md)。
- 用发布版（`/Applications/Mochi.app`）截图，这样不会出现开发版的英文菜单和「dev」字样。
- 只截浅色外观。
- 只用测试数据：先备份真实的配置和历史记录，换上测试用的配置、书签和历史记录，截完还原。网页用本地受控页面或公开的中性页面。不出现用户真实的历史记录、书签、登录态，也不截视频画面本身。
- 文件放 `docs/guide/images/`，英文短横线命名。
- 下面几种按窗口 ID 截不到，一律标「需人工截图」，或者改用文字说明：
  - 托盘菜单（菜单栏图标不作为窗口暴露）。
  - 幽灵模式半透明浮在其他应用上面的效果（按窗口截只拍得到 Mochi 自己）。
  - 展开状态的菜单。
- 本文件里截图位的写法：`📷 images/<文件名>.png — <内容>（<截法>）`。
- 正文里还没截的图，统一写成占位注释：`<!-- 📷 images/<文件名>.png — <内容>（<截法>） -->`。`images/` 一律指 `docs/guide/images/`，README 里也这样写，方便按文件名搜到所有截图位。补截图时把注释换成图片引用，路径改成相对于当前页面的写法。

## CONTRIBUTING.md（大纲）

1. 项目结构：Swift 项目在 `macos/`。
2. 开发：`swift build` / `swift test` / `swift run Mochi`，以及 `swift run` 为什么必须带产品名；`open macos/Package.swift`。
3. Xcode 工程只用来产出可分发的 `.app`。
4. 打包与发布：`package.sh`；版本号从 git tag 推导；用 `MOCHI_VERSION` 预演；推 tag 触发发布。
5. Issue 追踪：链接到 `docs/agents/issue-tracker.md`。
6. 文档导航：`CONTEXT.md`（领域术语）、`docs/adr/`、`docs/agents/`、`docs/design-language.md`、`docs/guide/`（用户手册）。
7. 修改界面文案时同步更新手册：改界面文案、默认热键、设置项时，`git grep` 一遍 `docs/guide/`。

## 教程

### `tutorials/first-steps.md` 上手：把视频放在桌面角落，边工作边看

- **读者目标**：第一次打开 Mochi 的人，十几分钟内完整走一遍核心用法，知道它跟普通浏览器的区别。
- **前提**：已按 README 装好并打开过一次。
- **要回答的问题**（按操作顺序）：
  1. 打开后看到的空页面是什么？上面的热键速览怎么看？
  2. 怎么在地址栏打开一个网页？以哔哩哔哩为例，并说明任何视频网站都可以。
  3. 怎么把窗口拖到屏幕角落、调成合适的大小？吸附到边缘是什么感觉？
  4. 怎么进入幽灵模式（⌥G 或工具栏按钮）？进去之后窗口发生了什么变化？为什么点不到它了？
  5. 不切换应用，怎么暂停 / 播放（轻按右 ⌥）、后退（连按两次右 ⌘）、前进（连按两次右 ⌥）？
  6. 怎么一键把窗口藏起来（⌥H），再按一次让它回来？为什么回来后视频没有自动继续播放？
  7. 怎么回到普通模式（再按 ⌥G，或点菜单栏的 Mochi 图标）？
  8. 关掉窗口后 Mochi 还在哪里？下次打开是什么样？
  9. 接下来可以看什么：链接到视频控制、幽灵模式、设置参考。

### `how-to/troubleshooting.md` 故障排除

- **读者目标**：带着一个症状进来，找到原因和做法。
- **格式**：每条写「症状 → 原因（一句话）→ 怎么做」，原因需要展开时链接到原理说明页。相关操作页末尾也链接回对应的条目。

  - 在系统设置里打开了摄像头、麦克风或下载文件夹权限，Mochi 里还是用不了。（迁自 README）

## 原理说明

### `explanation/what-is-mochi.md` Mochi 是什么，不是什么

- **读者目标**：理解 Mochi 的定位，不拿它当 Safari 用，再为缺少某个功能感到困惑。
- **要回答的问题**：
  - 为什么是一个窗口只放一个网页，没有标签页，也不能开多个窗口？
  - 为什么关闭窗口就是真的关闭，而不是收起来？
  - 为什么没有浏览器扩展、书签栏、书签文件夹，也不同步？
  - 为什么只有 macOS 版？
  - 它适合的场景，和不适合的场景（日常主力浏览器）。

### `explanation/ghost-mode-design.md` 幽灵模式为什么这样设计

- **读者目标**：明白幽灵模式各种「限制」背后的道理。
- **要回答的问题**：
  - 为什么置顶、透明、点击穿透、不抢焦点、隐藏工具栏是一起开关的，不能单独开？
  - 为什么幽灵模式里不能点网页，想操作必须先退出？
  - 为什么网页这时的请求一律「不打扰」地处理掉？
  - 为什么普通模式不置顶？
  - 隐藏窗口为什么只在幽灵模式里有？为什么隐藏时暂停视频，恢复时却不自动播放？

### `explanation/how-keys-are-heard.md` 按键是怎么被 Mochi 听到的

- **读者目标**：明白为什么有的键会被占用、有的不会，以及为什么有的键需要权限。
- **要回答的问题**：
  - 「占用」（全局热键、组合键触发的映射）和「只旁听」（视频控制、轻按或连按两次触发的映射）有什么区别？
  - 为什么占用会让这个组合在其他应用里失效？
  - 为什么系统把只带 ⌥ / ⇧ 的组合键当成打字，需要辅助功能权限才能旁听？
  - 为什么视频控制默认用轻按和连按两次？
  - 为什么默认热键避开了系统常用的快捷键？

### `explanation/privacy.md` Mochi 记下什么、不发给谁

- **读者目标**：放心使用，并分清三种容易混淆的「权限 / 数据」。
- **要回答的问题**：
  - 历史记录和地址栏建议只来自本机，输入的内容不会发给搜索引擎。
  - 网站图标是 Mochi 自己下载的，不经过第三方服务。
  - 网页权限（Mochi 允许网站做什么）、系统权限（macOS 允许 Mochi 做什么）、网站数据（网站存在 Mochi 里的东西）三者有什么区别，各自在哪里管理？
  - 为什么清除浏览数据不会动书签？

### `explanation/unsigned-app.md` 为什么第一次打开会被拦下

- **读者目标**：理解两件让人不安的事：被系统拦下、升级后权限失效。它们是预期内的，而且是安全的。
