# 为什么第一次打开会被拦下

装好 Mochi 后第一次打开，系统提示无法验证开发者，或者无法确认它不含恶意软件；升级之后，系统设置里的辅助功能开关明明开着，却不起作用。这两件事看着让人不安，其实都在预期之内，原因是同一个：Mochi 目前没有经过苹果公证。怎么放行，见 [README 的「安装」一节](../../../README.md#安装)。

## “没有经过苹果公证”是什么意思

从网上下载的应用，macOS 会先检查两样东西：

- **签名**：开发者用苹果发的开发者证书给应用签名，系统由此知道它是谁做的、下载之后有没有被改过。
- **公证**：开发者把签好名的应用提交给苹果做自动安全扫描，通过后，系统打开它时就直接放行。

公证只接受用开发者证书签名的应用，而这种证书要加入苹果的付费开发者计划（每年 99 美元）才能申领，苹果没有给个人开源作者的免费途径。Mochi 目前是个人开源项目，还没有这张证书，所以只做了最简单的一种签名（ad-hoc 签名）：它能证明应用在签名之后没有被改过，但说明不了是谁做的。系统看到这样一个从网上下载来的应用，就会先拦下来，让你自己决定要不要打开。

被拦下不代表 Mochi 有问题，只是系统没办法替你确认。Mochi 的源代码全部公开在 GitHub 上，[Releases](https://github.com/asfamilybank/mochi/releases) 里的安装包也是 GitHub 上公开的自动构建流程从这份源代码生成的。你也可以按 [CONTRIBUTING.md](../../../CONTRIBUTING.md) 自己从源代码构建，自己构建的应用不会被拦。

## 为什么放行一次之后就不会再拦

浏览器下载文件时，会给它打上一个“来自网络”的隔离标记，系统只对带这个标记的应用做上面的检查。

- 在「系统设置 › 隐私与安全性」里点「仍要打开」，系统会记住你已经同意打开这个应用。
- 在终端执行 README 里那条命令，是直接把隔离标记去掉。

两种方式都只对你放行的那一份 Mochi 有效，不会放松系统对其他应用的检查。之后每次打开都不会再问。

升级时你下载的是一份新的安装包，它又带上了隔离标记，所以新版第一次打开时会再被拦一次，再放行一次就好，见[升级 Mochi](../how-to/upgrade.md)。

## 为什么每次升级后都要把辅助功能移除、再重新添加

系统权限由系统按应用的身份记下。有开发者证书的应用，身份就是“哪个开发者的哪个应用”，换了版本也不变，所以授权会一直有效。Mochi 只有 ad-hoc 签名，系统只能按“这一版应用本身”来认它，每发布一个新版本，在系统眼里就是一个新的身份。

于是升级之后，「系统设置 › 隐私与安全性 › 辅助功能」里那个开着的开关，记的还是旧版的身份，对新版不起作用。Mochi 也分辨不出“开关关着”和“开关开着但对不上”这两种情况，所以设置里的提示总是写着：如果系统设置里已经打开，请先移除 Mochi 再重新添加。

只把开关关掉再打开没有用，因为那改的还是旧版的那条记录。把 Mochi 移除、再添加，系统才会按新版的身份重新记一条。具体步骤见[升级 Mochi](../how-to/upgrade.md#重新添加辅助功能权限)。

## 以后会不会改变

计划中。等 Mochi 有了开发者证书、能通过公证之后，第一次打开不会再被拦，升级后也不用重新添加辅助功能权限。
