# 幽灵模式为什么这样设计

幽灵模式有不少看起来像限制的地方：几项效果不能单独开关，里面不能点网页，网页弹出的东西会被直接处理掉。这一页讲这些设计背后的道理。

Mochi 想解决的问题只有一个：你在别的应用里专心做事时，网页能一直待在眼前，而且你不用切换过去就能控制它，比如暂停视频。幽灵模式就是为这一件事准备的状态，下面每一条都从这里出发。

## 为什么几项效果总是一起开关

进入幽灵模式时，工具栏隐藏、窗口变透明、置顶、点击会穿过窗口、不抢焦点，这五件事同时发生；退出时同时撤销。你不能只开其中几项。

原因是单独拿出任何一项，要么没用，要么碍事：

- 透明了却不能穿透，窗口看不太清，却照样挡着下面的东西，你点不到被它盖住的按钮。
- 能穿透却不置顶，窗口很快就被其他窗口盖住，等于没有。
- 置顶了却会抢焦点，你在别的应用里打的字可能跑进网页里。
- 置顶了却不透明，就是一块挡在屏幕上的板子。

只有五件事一起发生，才是“浮在眼前、又像不存在一样”。把它们做成一个开关，你只需要记住一个热键，也不用琢磨哪种组合才对。

透明度可以调，但这不算拆开：它调的是幽灵模式“透明到什么程度”，不是“要不要透明”。

## 为什么幽灵模式里不能点网页

点击会穿过窗口，是幽灵模式最重要的一点：网页就浮在你正在用的应用上面，你点在那块区域，就是想点下面的应用。如果网页还能接收点击，这两件事就冲突了，Mochi 没法猜出你这一下是想点谁。

所以幽灵模式里的规则很简单：要操作网页，先退出，做完再回去。按 ⌥G（Option + G）一下就能来回切换，不需要更多的中间状态。

最常用的几种操作不用退出也能做：视频的暂停、播放、后退、前进交给[视频控制](../how-to/video-control.md)，网站自带的快捷键交给[热键传递](../how-to/hotkey-forwarding.md)。它们靠按键工作，不需要点击，也不需要 Mochi 获得焦点。

## 为什么网页这时的请求会被直接处理掉

幽灵模式下的窗口从不成为前台窗口。网页如果在这时弹出一个对话框、要用摄像头，或者打开一个登录小窗，Mochi 只有两种不好的选择：

- 把对话框弹出来等你回应：那就得抢走你正在用的应用的焦点，甚至退出幽灵模式，打断你手上的事。
- 把请求挂着，等你哪天退出幽灵模式再说：网页会一直卡在那里，你可能根本不知道视频为什么不动了。

所以 Mochi 选择当场了结这些请求，而且都按最保守的方式了结：提示自动关掉、需要确认的按取消处理、摄像头和麦克风拒绝、下载不询问直接存、登录小窗不打开。这样网页不会卡住，你也不会被打扰，更不会在你没看见的时候把摄像头交给某个网站。

具体每一项怎么处理，见[三种模式对照](../reference/modes.md#网页发起的请求)。

## 为什么普通模式不置顶

普通模式下的窗口不透明、能点、会接收键盘输入，跟别的窗口没有两样。如果这样一个窗口还一直浮在最上层，它会挡住你在别的应用里要看的东西，你却没法让鼠标穿过去。

置顶只有在窗口同时透明、能被点穿的时候才有意义，而那正是幽灵模式。所以 Mochi 不单独提供“置顶”开关：想让网页浮在上面，就进入幽灵模式。

## 为什么隐藏窗口只在幽灵模式里有

隐藏窗口是给这种时刻准备的：网页浮在你正在用的应用上面，有人走过来，你需要它立刻消失，而且不能切换到 Mochi 去关它。这正是幽灵模式下才会遇到的情况。

普通模式下的窗口是一个普通的 macOS 窗口，你本来就能用系统的方式收起它，比如最小化，或者隐藏整个应用，不需要 Mochi 再做一套。

## 为什么隐藏时暂停视频，恢复时却不自动播放

你把窗口藏起来，意思是“我现在顾不上看”。如果视频接着播，等你回来，它已经播过去一大段，你还得往回找。所以隐藏的那一刻，Mochi 会暂停网页里所有正在播放的视频和音频，让它停在你离开时的位置。

窗口回来时，Mochi 不替你按播放：你往往要先看清画面、想起刚才看到哪儿，再决定什么时候继续。而且如果自动播放，还可能把你本来就暂停着的视频也播起来。接着播放只需要按一下视频控制的播放键，什么时候继续由你决定。

隐藏期间你也可以用视频控制让视频接着播放，比如只想听声音的时候。

## 为什么重新打开后总是回到普通模式

退出 Mochi 再打开，或者关掉窗口再打开，窗口总是先回到普通模式。

如果 Mochi 记住上次的幽灵模式，你可能早就忘了这件事：下次打开 Mochi 时，桌面上直接浮着一个半透明、点不到的窗口，你一时想不起它为什么是这样、该怎么让它恢复。先回到普通模式，你总能看见并操作这个窗口，想进幽灵模式时再按一下 ⌥G 就行。
