# Normal Mode 复用原生窗口装饰处理拖动/关闭/最小化，不做全自定义无边框窗口

> 2026-09-02 更新：本 ADR"原生标题栏 + 下方独立自绘工具栏，两行不重叠"这一具体结论已被 [ADR-0009](0009-unified-native-toolbar-chrome.md) 取代（改成单行 unified toolbar），但"不重造原生拖动/按钮交互"这条核心原则仍然成立。保留下文作为历史记录。

早期构想里"支持无边框窗口"容易让人以为整个窗口（包括拖动、关闭、最小化）都要自己实现一套自绘标题栏逻辑。最终决定 Normal Mode 下保留系统原生的窗口装饰（原生标题栏、原生的关闭/最小化按钮和拖动手感，即标准 `titled` 样式的 `NSWindow`），只在原生标题栏下方额外加一条自绘工具栏（地址栏 + 其他工具按钮），两者各占各的窗口高度，不重叠、不挤压网页内容区域。

这样可以省掉重新实现窗口拖动物理、原生按钮点击态、双击最大化等一整套容易踩坑的交互逻辑，只把自定义能力聚焦在"地址栏和工具按钮"这个真正需要定制的部分。"无边框"这个特性实际只用在 Ghost Mode——Ghost Mode 下原生装饰和自绘工具栏会一起隐藏（切换窗口的 `styleMask`），才呈现真正的无边框悬浮观感。

## Consequences

- Normal Mode 下窗口看起来更像一个"精简版浏览器窗口"而不是完全定制的挂件外观，这是刻意的取舍。
- 需要能在运行时动态切换窗口的 `styleMask`/标题栏可见性（Normal Mode 显示、Ghost Mode 隐藏），这是标准 `NSWindow` 能力。
