# 悬浮模式是第三种绑定状态，不是 Ghost Mode 的一个属性

用户需要一种窗口：像 Ghost Mode 一样无边框、半透明、悬在别的应用之上，但能点击、能打字、能获得焦点，用起来和普通窗口一样，也能一键隐藏。最直接的做法是给 Ghost Mode 加一个「允许交互」的属性，但这条路被否决了。[ADR-0012](0012-ghost-mode-as-pure-invisibility.md) 给 Ghost Mode 定的判据是「永不获得焦点、任何需要交互的东西都不属于它」，「允许交互」正好站在判据的反面。而且网页请求一律不打扰、本地快捷键靠「没有 key window」自动失效、进入时交还焦点，这些规则全都建立在「Ghost Mode 不可交互」上，加了属性就得每处分支。所以新增一个与它并列的 **Float Mode（悬浮模式）**，按 [ADR-0006](0006-ghost-mode-is-a-bundled-state.md) 的原则做成绑定的复合状态：两个模式各自内部一致，分界线就是焦点。

- **绑定的内容**：原生窗口装饰和工具栏隐藏，只留网页内容；透明度降到自己的设定值（默认 0.8，与 Ghost Mode 分开设置）；不做鼠标穿透；可以获得焦点，焦点和键盘鼠标的行为与 Normal Mode 无异。
- **置顶是偏好，不是开关**：默认置顶，可以在设置里关掉。按 ADR-0012 的分类，「这个模式是什么」必须绑定，「这个模式怎么表现」可以是偏好，透明度可调就是先例。置顶在这里属于后者。它只能是设置面板里的一个勾选框，不加热键、托盘项或标题栏按钮，否则就退回了 ADR-0012 砍掉的那种 Pin 开关。Ghost Mode 仍然始终置顶。
- **切换**：全局热键默认 ⌥F。⌥F 和 ⌥G 都是「进入这个模式；已经在其中就回到 Normal Mode」，悬浮与幽灵之间可以直接互切。不做一个键按顺序轮换三个模式：慌乱中按之前还得先想清楚当前在哪个模式。托盘菜单加一项「悬浮模式」。Normal Mode 工具栏暂不加悬浮模式按钮（幽灵模式有），入口只有热键和托盘；加按钮会让 392pt 最小宽度和 452pt 幽灵按钮隐藏阈值都得重新实测，等真用下来觉得需要再加。应用重启或 Widget 重新打开一律回到 Normal Mode。
- **焦点**：进入悬浮模式时激活 Mochi，但在隐藏状态下从幽灵模式切过来时不激活。进入 Ghost Mode 或 Hidden 时把焦点交还给之前的 app。
- **本地快捷键**：照常可用。依赖工具栏的两个命令（⌘L 打开位置、⌘D 添加书签，后者的编辑气泡挂在地址栏下面）置灰。
- **只属于 Ghost Mode 的功能**：视频控制和热键传递在悬浮模式下不生效。网页的交互请求照普通窗口处理，Popup Window 照常打开，Widget 置顶时 Popup Window 也提升到同一层级，否则会被压在底下。

## 原生标题栏悬停时向外长出

移动、缩放和关闭都交给原生窗口，Mochi 不另造一套（ADR-0012）。做法仿照「iPhone 镜像」：

- 窗口保留 `.titled`，只是标题栏透明、交通灯藏起来（按钮 `alphaValue = 0`，此时它们也点不到）。没有走 Ghost Mode 去掉 `.titled` 的路，这样就绕开了那条路上的三个坑：窗口原生就能成为 key window，`window.toolbar` 不会被丢掉，标题栏拖动和边缘缩放都是系统自带的。
- 鼠标移到窗口顶部边缘附近时，窗口向上加高一个标题栏的高度，露出交通灯和不透明的标题栏背景；鼠标离开时缩回。网页贴着窗口底部、高度固定，所以它在屏幕上的位置和尺寸都不变，页面不重排，也不会收到 `resize` 事件（原型实测，带动画逐帧采样也一样）。不选「盖在网页上」：那样每次悬停都会挡住页面顶部。也不选「把网页往下推」：那样会改 `obscuredContentInsets`，每次都要重排。
- 边缘缩放随时可用，看不见边框也一样。绿色按钮禁用，既不全屏也不缩放：一个置顶、半透明的窗口铺满屏幕，悬浮就没有意义了。
- 处于 Hidden 时不响应悬停。

**进入悬浮模式时，网页留在屏幕上原来的位置。** 窗口从上方去掉 Normal Mode 工具栏那 52pt，回到 Normal Mode 时再长回来。Normal Mode 下网页的可视高度本来就扣掉了工具栏，所以切换模式时页面不重排。在悬浮模式下拖动时，网页顶边不能进入可见区域上沿往下一个标题栏高度的范围，Snap 也吸附到那里，于是向外长出的那一条永远有地方放。这正是「iPhone 镜像」的表现：它怎么拖都贴不到顶。如果不这样限制，窗口贴着顶边时 AppKit 会在 `setFrame` 里通过 `constrainFrameRect` 把整个窗口往下推，网页就会跟着跳（实测）。

## Hidden 两个模式共用，并且可以连 Dock 和 ⌘Tab 一起隐藏

Hidden 从 Ghost Mode 的内部维度改成两个模式共有，热键也是同一个（默认 ⌥H）。慌乱中按下时，不该还要先想自己在哪个模式。Normal Mode 下仍然什么也不做，它是普通窗口，用系统的 ⌘M。悬浮与幽灵之间切换时隐藏状态保持不变，回到 Normal Mode 时取消。取消隐藏只恢复可见，从不激活，和 Ghost Mode 原来的行为一致。Hidden 期间窗口同时打开鼠标穿透：悬浮模式本身不穿透，可一个看不见的窗口不该接住本来要点到下面应用上的点击。Hidden 期间，不论处于哪个模式，网页的交互请求都按 Ghost Mode 的不打扰方式了结：不能往一个看不见的窗口上弹询问框。

新增一个设置「隐藏时也从 Dock 和 ⌘Tab 中移除」，默认关闭，做法是运行时在 `.regular` 和 `.accessory` 两种激活策略之间切换。**两处只能一起隐藏**：能把 Mochi 从 Dock 拿掉的激活策略（`.accessory`、`.prohibited`）都会同时把它从 ⌘Tab 里拿掉，公开 API 没法只藏一处，所以原先设想的四选一下拉框做不出来。Mochi 正在前台时切到 `.accessory`，会立刻失去前台，焦点回到之前的 app，正好就是进入 Hidden 要做的事。切回 `.regular` 时不会自己激活，也符合「取消隐藏从不激活」（均为实测）。

**这个切换最多每秒一次。** 两次切换间隔太短时，Dock 会留下重复的图标，进程退出后也不消失（实测：带 bundle id 的 `.app` 也一样，间隔约 1 秒时不出现）。所以窗口可见性立即变化，激活策略的切换则要等到距离上一次满 1 秒；在这之前又按了一次隐藏，就直接取消待执行的恢复。连按 ⌥H 时窗口照样即时响应，最坏情况是 Dock 图标晚 1 秒才消失。代价是用户要接受 Dock 图标当场消失和出现时的系统动画。隐藏期间托盘图标保留，它和热键是把窗口找回来的两条路。

## Considered Options

- **给 Ghost Mode 加「允许交互」属性**：见第一段。它其实就是 ADR-0012 砍掉的「召唤工具栏」，只不过把「隐身状态里开一个可交互的洞」开到了整个窗口。
- **让 Normal Mode 可以选无边框、置顶、透明度**：Normal Mode 的定位是「就是一个普通 macOS 窗口」，置顶也已经从它身上拿掉了。再往里加这些，那条线就模糊了。
- **完全去掉边框，自己做拖动条**：要重造拖动、缩放和成为 key window 的能力，还会撞上去掉 `.titled` 之后 `window.toolbar` 被丢掉的坑。

## Consequences

- ADR-0012 里「Hidden 仅在 Ghost Mode 生效」和「置顶只在隐身场景下才有意义」两处被本 ADR 修改。Snap 不再是 Normal Mode 专属，悬浮模式下也生效（ADR-0012 当初排除它的理由是「Ghost Mode 下窗口拖不动」，这个理由对悬浮模式不成立）。
- ⌥F 是 Carbon 全局热键，只要 Mochi 在运行，就会从所有应用手里拿走它：打不出 `ƒ`，终端开了「Option 当 Meta」时会失去 `M-f`（向后跳一个单词）。和 ⌥G/⌥H 是同一笔取舍，用户可以改绑。
- 设置面板原先的「幽灵模式」面板改名为「窗口模式」，分悬浮模式、幽灵模式、隐藏三组。空页面的热键速览加上 ⌥F，隐藏那条的范围说明改为「隐藏窗口（悬浮或幽灵模式下）」。
- 悬停显示标题栏用的是鼠标跟踪区，合成的 `mouseMoved` 触发不了它，所以这部分只能真机验证。真实拖动标题栏、边缘缩放、双击标题栏不缩放，都要列进真机验证清单。
