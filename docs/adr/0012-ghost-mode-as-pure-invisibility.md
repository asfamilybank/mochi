# Ghost Mode 收敛为纯隐身状态：需要交互的东西一律不属于它

[ADR-0006](0006-ghost-mode-is-a-bundled-state.md) 立下的原则是"Ghost Mode 是一个绑定的复合状态，不是若干独立开关的自由组合"，这条仍然成立。但它当初往这个状态里捆进了一个自相矛盾的东西——次级热键召唤工具栏浮层（召唤期间临时关闭穿透使其可交互），同时又把置顶（Pin）明确排除在外、定义成两种模式下都可用的常规窗口功能。这次把这两个决定都推翻，改用一条更锐利的判据重新划线：

> **Ghost Mode 是一个不可拆的、永不获得焦点的纯隐身状态。任何需要用户交互的东西都不属于它；任何只在隐身场景下才有意义的窗口属性都属于它。**

按这条判据：

- **召唤工具栏整条能力砍掉。** 用户真要操作工具栏，就该先退出 Ghost Mode。"隐身状态里开一个临时可交互的洞"正是 ADR-0006 花力气否掉的中间态，只是当初没认出它。
- **Pin 内化为 Ghost Mode 的固有属性。** 置顶只在"悬在别的窗口之上看"这个场景里才有意义，而那就是 Ghost Mode。Ghost Mode 下始终置顶、不可关闭；Normal Mode 恢复普通窗口层级。工具栏的 Pin 按钮、Pin 热键、Pin 的持久化配置一并移除。
- **Normal Mode 就是一个普通 macOS 窗口。** 凡是原生窗口已经提供的能力（拖动、缩放、最小化、关闭），Mochi 不再造第二遍——`⌥⌘S` 循环预设尺寸的热键因此也砍掉。
- **Ghost Mode 永不获得焦点。** 进入/停留在 Ghost Mode 期间窗口不成为 key window；只有**退出** Ghost Mode 时才激活。原实现在恢复窗口可见性时调用 `makeKeyAndOrderFront`，会把焦点从用户正在使用的应用抢走，与项目核心承诺（"全程不需要窗口获得焦点、也不抢占用户当前焦点"）直接冲突。

## "鼠标移入即隐藏"由状态组成降级为偏好

ADR-0006 把"鼠标移入即隐藏"点名捆进了 Ghost Mode。现在把它拆出来，做成一个可关闭的偏好（默认开启），并且行为从"移出不恢复"改成**移出即恢复**。

这不是对 ADR-0006 绑定性原则的违反，而是对它的一次分类修正：透明度 + 穿透 + 无原生装饰 + 始终置顶 + 不抢焦点这五件事说的是"这个模式**是什么**"，必须一起发生；而"鼠标压上来时让开"说的是"这个模式**怎么表现**"，跟 Ghost Mode 的目标透明度取值是同一类东西——没人会说"透明度可调"破坏了绑定性。

行为之所以从"移出不恢复"改成"移出即恢复"，是因为它的**理由**变了。原理由是防抖（怕鼠标划过导致闪进闪出）；新理由是"穿透状态下 Widget 挡视线、要给鼠标让路"，那就是避让语义，而避让的自然行为是鼠标一走就回来。若仍保持"不恢复"，它就退化成一个与下述隐藏热键功能完全重合、却更容易误触的第二套隐藏手段。

## 四种"看不见"各自归属明确

这次划线的直接产物是一张不重叠的可见性分工表——这是整个设计里最容易被后来者搞混的部分：

| | 触发 | 生效范围 | 窗口 | 页面 | 恢复方式 |
| --- | --- | --- | --- | --- | --- |
| 半透明 + 穿透 | 进入 Ghost Mode | — | 在 | 继续 | 退出 Ghost Mode |
| **Hidden**（老板键） | 全局热键 | 仅 Ghost Mode | 在 | **继续** | 再按热键 / 托盘 |
| **鼠标移入避让** | 鼠标移入（偏好，默认开） | 仅 Ghost Mode | 在 | 继续 | 鼠标移出即恢复 |
| **关闭 Widget** | `⌘W` | 仅 Normal Mode | **销毁** | **停止** | 托盘 / Dock 图标 → 完整重新启动 |

**Hidden 必须用 `alphaValue = 0` 实现，不能用 `orderOut`。** 老板键的语义要求是"完全看不见但页面还在跑"（视频不能停），而 `orderOut` 掉的窗口会被 WebKit 判定为被遮挡（occluded）从而节流定时器、可能暂停渲染。移出屏幕外（`setFrameOrigin`）虽然也能保证渲染，但需要额外记账原坐标，会跟 Snap 和多显示器越界收回逻辑打架。

由此得出一个接缝层面的推论：**"隐藏"在 `PlatformOps` 上不再是一个独立概念**。`setWindowHidden` 与 `setContentOpacity` 会争抢同一个 `NSWindow.alphaValue`，因此前者被合并掉——编排核心自己算出一个**有效不透明度**（Hidden 或避让触发 → 0；Ghost → 目标透明度；Normal → 1.0），平台层只负责照着设。可见性从两个互相打架的 op 收敛成一个值。

## Consequences

- ADR-0006 的两条具体结论作废：① Ghost Mode 包含"召唤工具栏"能力；② Pin/Snap 与模式无关、两种模式下都可用。其"Ghost Mode 是绑定的复合状态、不做自由组合开关"的核心原则延续，并被"需要交互的东西不属于它"这条判据进一步锐化。
- Snap（拖拽磁性吸附）**不**跟着 Pin 内化——它只在用户手动拖拽时起作用，而 Ghost Mode 下窗口穿透且经常不可见、根本拖不动。Snap 保留为 Normal Mode 专属、可在设置中关闭的功能；吸附阈值不再暴露为配置项。
- Ghost Mode 下没有刷新，也没有缩放。这两个动作降级为 Normal Mode 的本地快捷键（`⌘R` / `⌘+` / `⌘-` / `⌘0`，对齐 Chrome 且不可自定义），只剩"切换 Ghost Mode"和"隐藏/显示 Widget"两个全局热键——后者仅在 Ghost Mode 生效。因为本地快捷键需要 key window 才会被派发，而 Ghost Mode 永不获得焦点，"只在 Normal Mode 生效"这个约束不需要任何额外判断逻辑，是免费的。
- Widget 关闭后应用仍在托盘运行，但此时两个全局热键都是 no-op——Widget 不存在时"隐身"无所指。打开 Widget 只有托盘菜单和 Dock 图标两条路。**这使 Dock 图标成为一条功能性入口**，将来若把激活策略改成 `.accessory`（不占 Dock），会消灭这条入口，届时托盘是唯一出口。
- `CONTEXT.md` 里 Ghost Mode 与 Pin/Snap 两条术语定义随之重写，新增 **Hidden** 与**鼠标移入避让**两个术语。
- 已关闭的 #5（Pin）与 #10（Ghost Mode 工具栏召唤）所描述的已上线行为被推翻，按仓库约定新开 issue 引用旧记录，不重开旧票。
- 设计稿 `design/mochi/GhostToolbar.dc.html` 的内容作废，从画布中摘除但保留文件作历史存档——性质同被取代的 ADR。
