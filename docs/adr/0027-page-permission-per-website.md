# 网页权限按网站区分

设置原本一律全局生效，理由是 Widget 只承载一个网页。摄像头和麦克风是例外：同一个 Widget 可能这会儿开会议、过会儿开别的网站，全局「允许」等于把摄像头交给每一个打开过的网站。所以网页权限改成 Safari 和 Chrome 的模型：**每种权限有一个「访问其他网站时」的默认值（询问 / 拒绝 / 允许），外加按网站的例外**。原来的全局选项变成默认值。其他设置（自动播放、弹出式窗口、缩放）仍然全局：自动播放 WebKit 只在创建 web view 时读，没法按网站区分；另外两项在通常只开一个网站的 Widget 里，按网站区分没有意义。

「网站」按**发起请求的 frame 的主机名**划分。询问由 Mochi 自己弹框（不再交给 WebKit 自带的框，因为那个框不会告诉我们用户选了什么），沿用 Chrome 的三个选项：「访问此网站时允许」和「不允许」记成例外，「仅这次允许」只管这一次页面加载。每条例外记下最后修改时间，供「清除浏览数据…」按时间范围清除。

## Considered Options

- **按可注册域名划分**（`meet.google.com` 允许就等于整个 `google.com` 允许）：会放宽授权范围。网站数据只能按可注册域名列出和删除，那是 WebKit 的限制，不该反过来决定权限的粒度。设置里「管理网站和数据…」按可注册域名分组，展开后列出各个主机名的例外。
- **Safari 那种不记住选择的询问框**：例外只能去设置里一条条手动加，实际上永远不会有人加。
- **只记住「允许」**：被拒绝过的网站每次打开都会再问。

## Consequences

- 改变了 #69 的一个行为：Ghost Mode 下只有 **Widget 页面**的请求被直接拒绝；Popup Window 是普通窗口（用户可能正在里面登录），它的请求照常询问。
- 设置结构跟着调整：「网页内容」面板改名为「网站」，按权限查看（左侧列出权限，右侧是例外列表加默认值）；新增「隐私与安全性」面板，按网站查看和删除网站数据（「管理网站和数据…」「清除浏览数据…」），HTTP 警告也从「高级」搬到这里。在「管理网站和数据…」里，删除一个网站的数据和重置它的网页权限是两个分开的动作；「清除浏览数据…」里网页权限例外是单独一项、默认不勾。
