# Widget 在 v1 中一一绑定单个固定 URL，不做多标签页、不做多窗口并存

早期构想里同时提到"支持创建和管理多个独立的网页浮窗"和"多标签页、热键切换（类似 Chrome Cmd+1/2/3）"。讨论后 v1 大幅收敛范围：整个应用在同一时刻只呈现一个 Widget 窗口、加载一个固定 URL，既不支持同一份配置的多标签页，也不支持同时开出多个独立的 Widget 窗口实例。

这是为了让 v1 尽快做出一个可用、体验扎实的核心闭环（单窗口 + Ghost Mode + 热键控制），而不是同时啃"多窗口生命周期管理"和"标签页状态管理"两块复杂度。多标签页与多窗口并存都作为明确的 v2 路线图方向，不是被砍掉。

## Consequences

- v1 不需要设计 Tab 实体、标签页 UI，也不需要按 Tab 拆分配置持久化。
- 顶部工具栏（Normal Mode 下用于拖动窗口 + 关闭/最小化）不需要包含标签页，可以简化成一条最简的自绘标题栏。
- 若用户想同时"挂"多个网页，v1 阶段只能开多个应用进程实例、各自独立配置——应用层面不提供直接支持，是已知的临时权宜方案，v2 再补多窗口能力时一并解决。
