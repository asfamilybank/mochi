# 历史记录按次记录访问，图标跟着访问走

历史记录原本是「一个网址一条」：只记最近访问时间、访问次数和最后拿到的标题（#97）。结果它更像一份网址清单，而不是时间线：周一和周三都看过的页面，只会出现在周三；同一天在两个页面之间来回切换，也看不出先后顺序。现在改成 Chrome 那样的时间线，**Widget 主页面的地址每变一次，就记一次访问**。显示时也是一次访问一行，不合并，也不去重。窗口和「历史记录」菜单都是这样。

每次访问记的是**那一次**的标题和站点图标：页面后来改了标题、网站换了图标，都不会改写更早的记录。图标的字节按内容哈希只存一份，访问里只记哈希。语义上仍然是每次访问有自己的图标，只是相同的字节不重复存，否则一年几十万次访问会把 `History.db` 撑到几百 MB。删除、保留期限和「清除浏览数据」都按访问时间删除访问；某张图标不再被任何访问引用时，也一起删掉。

## Considered Options

- **网址表加访问表两张表**（Chrome 的 `urls` + `visits`）：Chrome 单独存网址，是为了地址栏补全要用的网址级统计。Mochi 没有补全，拆开只会多一层 join，还要处理网址行的孤儿问题。
- **存储逐次记，显示时按天去重**（同一网址一天只显示一行）：这是在显示层丢掉访问，时间线就不完整了。
- **图标按 origin 记**（跟地址栏的缓存一致）：站点换了图标以后，旧记录也会跟着变，和「标题按访问记」的原则不一致。
- **迁移旧数据**：没有正式用户，旧表里也只有每个网址的最后一次访问，迁过来的时间线本来就是残缺的。

## Consequences

- 推翻了 #97 里「同一网址只有一条」的定义（`CONTEXT.md` 的「History」词条已同步修改）。
- 没有迁移：旧文件里的 `history` 表留着，不读也不删，时间线从空开始。
- 以后如果做地址栏补全，只从访问表计算，清除历史就会顺带清掉补全；如果给补全另加缓存，就必须接上所有删除路径。
