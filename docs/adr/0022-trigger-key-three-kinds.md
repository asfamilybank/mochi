# 触发键分三种：轻按、连按两次、组合键

[ADR-0020](0020-video-control-listens-never-intercepts.md) 给视频控制定了"单独轻按右侧修饰键"作默认键，用户可以改绑成普通键或组合键，但没有给用户明确的"选哪种方式"入口——录制框同时接受轻按和普通按键，靠用户自己猜。它还否决了双击修饰键，理由是"单击必须等约 0.25 秒确认不是双击"。

现在希望一颗修饰键能做两件事（比如右 ⌥ 轻按播放/暂停、连按两次跳到别处），而且设置里要能明确选择触发方式。

## 决定

- **触发键**分三种方式：
  - **轻按**：单独按一下一颗修饰键，左右算两颗不同的键（沿用 ADR-0020 的定义）；
  - **连按两次**：同一颗修饰键在固定间隔内轻按两次，每一次都必须满足轻按的定义，间隔不开放配置；
  - **组合键**：至少一个修饰键加一颗非修饰键。字母、数字、符号键至少要带 ⌃⌥⌘ 之一；F 键、方向键这类本身不产生字符的键单带 ⇧ 也行。单独 ⇧ 加字母不算，否则作为全局热键会让大写字母在所有 app 里打不出来。
- **轻按和连按两次只开放给视频控制和热键传递**，两者都只在 Ghost Mode 下监听。全局热键（切换 Ghost Mode、Hidden）仍然只能是组合键，继续走 Carbon——这样"普通模式下不监听键盘"这条不变。
- **同一颗键可以既设轻按又设连按两次**，代价是这颗键的轻按要等过连按间隔、确认不是连按两次才触发。延迟只落在两种方式都设了的那颗键上，其它键的轻按照旧立即触发；默认配置里没有任何连按两次，所以默认手感不变。视频控制和热键传递共用一套识别，跨区共用一颗键也按这条处理；两个功能设了完全相同的触发键仍是冲突。
- 组合键规则收紧前已经存进配置的不带修饰键的绑定照常生效，只是不能再新录这种组合。

这部分取代了 ADR-0020 对"双击修饰键"的否决：那条否决的前提是"双击会拖慢所有单击"，现在延迟只在用户自己把同一颗键两用时出现，是用户可见、自己选择的代价。

## 考虑过、否决的方案

- **同一颗键两用视为冲突**：保住轻按永远立即触发，但"一颗键两件事"正是这次要的东西。
- **轻按不等待，第二下再触发连按两次**：连按两次时两个功能都执行，暂停后又跳转，行为不可预期。
- **全局热键也开放轻按/连按两次**：轻按只能靠监听实现，等于普通模式下也要一直监听键盘，推翻 ADR-0020 "只在 Ghost Mode 期间监听"的隐私边界，还要为切换 Ghost Mode 本身索要「辅助功能」权限。

## Consequences

- 配置里视频控制和热键传递的触发键要能表达三种方式；旧配置项按原有形态读入，不需要迁移。
- 热键传递在同一节里并存两种占用语义：组合键走 Carbon 会占用，轻按和连按两次只监听不占用。
