# 悬浮模式的标题栏是网页上方一条透明的带子，悬停时淡入

[ADR-0035](0035-float-mode-as-a-third-bundled-state.md) 里「原生标题栏悬停时向外长出」的做法上线后（#151），真机用下来手感不好：

- 标题栏出现时整个窗口向上长 32pt，靠改窗口外框做动画，比单纯的淡入淡出生硬。
- 动画进行中指针离开，系统会漏发离开事件，只好在动画结束后再补判一次；窗口贴着顶边时，长高还会被系统往下推，于是又要在顶部预留 32pt（#149）。
- 触发区在网页里面，要把指针移进网页才会出现。

对照 iPhone 镜像的录屏：指针在画面顶边**上方**、还差一个标题栏高度时，标题栏就出现了；在左右上角的圆角旁、低于顶边时则不出现。由此判断它的窗口一直比画面高出一个标题栏，这条标题栏平时完全透明，指针进入这条带子时才淡入。没有公开 API 能做到「普通窗口悬停时显示标题栏」：`windowToolbarFullScreenVisibility(.onHover)`、`autoHideToolbar`、`NSTitlebarAccessoryViewController.fullScreenMinHeight` 都只对全屏窗口有效（macOS 26.5 SDK）。所以照这个思路自己做，取代 ADR-0035 的那一节和 #149 的顶部约束。

- **外框**：悬浮模式和幽灵模式下，窗口一直是「网页 + 上方 32pt 带子」。带子就是原生标题栏（无工具栏时的高度）。从普通模式进入时，窗口上沿只下移 52 − 32 = 20pt，网页在屏幕上不动、不重排。幽灵模式用同样的外框，带子永远不显示，所以两个模式互切时外框不变。
- **透明**：带子平时完全透明。网页视图本来就比可见区域往上多出 52pt（`obscuredContentInsets`），用一层裁剪视图把它裁在带子下沿，带子里什么也不透出来。窗口在这两个模式下始终不画背景色，透明度设成 100% 也一样。
- **触发**：触发区只是带子本身，跟 iPhone 镜像一样，网页（包括圆角旁）不触发。指针进入带子时，标题栏背景（`.titlebar` 材质）和交通灯淡入，离开时淡出，窗口外框从不因悬停改变。窗口挪动后再按指针的实际位置补判一次。隐藏窗口时不响应。
- **圆角**：网页上边两角一直裁成跟窗口一样的圆角（16pt，macOS 26.5 实测）。标题栏不显示时，网页单独看起来就是一个窗口；标题栏显示时，它的背景往下多延伸 16pt、垫在网页后面，把两个角缺出来的地方填满，网页像 iPhone 镜像的画面一样嵌在窗口里。背景垫在网页**后面**，不压在网页上。
- **顶部不再另设约束**：带子是标题栏，系统本来就不让标题栏跑到菜单栏后面，网页自然停在屏幕上沿往下 32pt 处。吸附照普通的贴边处理，作用在整个窗口上。
- **绿色按钮置灰**：照 ADR-0035 禁用。但光设一次保持不住：指针每次进入 key window 的标题栏，AppKit 都会在约 40ms 后把它重新启用，覆写 `isZoomable`、拦截 `validateUserInterfaceItem`、KVO 都挡不住（实测）。它每次进入只启用一次，所以标题栏显示后稍等片刻再禁用一次，之后整个悬停期间都保持禁用。禁用的绿色按钮还有两种样子：透明度正好为 1 时，系统给它叠一层提亮效果，画成浅灰；低于 1 时露出本来的深色圆点，跟 iPhone 镜像的禁用按钮一样（实测）。淡入时先深后浅会闪一下，所以标题栏显示时把它的透明度停在 0.99，一直保持深色。双击带子缩放的路径仍由 `windowShouldZoom` 拒绝。

## 后果

- 网页正上方那条看不见的 32pt 带子会接住点击：点在那里拖得动窗口，点不到下面的应用。iPhone 镜像也是这样，而且指针移过去时标题栏会先显示出来。
- 窗口贴着屏幕顶边时回到普通模式，工具栏比带子多出的 20pt 放不下，系统会把整个窗口往下推 20pt，网页也跟着下移。只在贴顶时发生，旧做法同样如此。
- macOS 26 上拖动标题栏由窗口服务器完成，只在松手时询问一次 `constrainFrameRect`（实测），所以吸附发生在松手那一刻，普通模式和悬浮模式都是如此。模式切换时 AppKit 会在下一个 runloop 再约束一次 Mochi 自己设的外框，这一次不吸附，否则贴近顶边的窗口会被拉上去 20pt。
