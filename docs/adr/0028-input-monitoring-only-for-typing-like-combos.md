# 视频控制只在绑了「像打字的组合键」时才请求输入监控

> 已被 [ADR-0029](0029-accessibility-only-for-typing-like-video-combos.md) 取代：实测授予输入监控后，⌥P 在其他应用里仍然收不到——全局监听对「打字」按键的过滤只认辅助功能。「只有不带 ⌃/⌘ 的组合键才需要权限」这条判断保留。

[ADR-0026](0026-system-permissions-requested-on-need.md) 以为视频控制（以及轻按/连按触发的热键传递）要靠**辅助功能**才能在其他应用里听到按键，于是默认配置的用户第一次进入 Ghost Mode 就会被弹辅助功能授权框，设置和托盘也一直挂着警告。实测（2026-10-12，macOS 26.5，Mochi 没有任何系统权限时）推翻了这两点：

- 全局按键监听（`NSEvent.addGlobalMonitorForEvents`）由 WindowServer 按**输入监控**（`kTCCServiceListenEvent`）把关，不是辅助功能——以前给了辅助功能能用，只是因为受辅助功能信任的应用也被放行。
- 没有输入监控时，WindowServer 也不是什么都拦：修饰键变化（轻按、连按两次）照常送达；带 ⌃ 或 ⌘ 的组合键（⌃⌥P）照常送达；**只带 ⌥ 和/或 ⇧ 的组合键（⌥P、⇧F5）被拦下**——它们会打出字符，系统按防键盘记录的口径当成打字。Carbon 全局热键（切换 Ghost Mode、Hidden、热键传递的组合键）本来就不需要权限。

所以决定：**Mochi 不再申请辅助功能；只有当视频控制里至少一个触发键是组合键、并且它既不带 ⌃ 也不带 ⌘ 时，才需要输入监控**。状态用 `IOHIDCheckAccess(kIOHIDRequestTypeListenEvent)` 查（能分出未询问 / 已拒绝 / 已授权），请求用 `CGRequestListenEventAccess()`，「打开系统设置」直达「输入监控」页；辅助功能已经授权的老用户也算已获得（它同样放行），不再追问。ADR-0026 的其余部分照旧：第一次进入 Ghost Mode 时最多自动请求一次（换用新的标记，因为问的是另一项权限）、已获得就不出现任何说明或按钮、授权后尽量即时生效。

## Considered Options

- **只要视频控制有组合键就算需要**：万一系统哪天收紧放行规则也不会漏，但会给 ⌃⌥P 这类本来就能用的绑定弹一个用不上的授权框，违反「用到时才请求」。
- **继续申请辅助功能**：它能控制其他应用，远超 Mochi 需要的「听按键」，权限要得越小越好。

## Consequences

- 放行规则是实测得出的，不是文档承诺。系统升级后要重新核对：没有权限时 ⌃⌥P 生效、⌥P 不生效。若规则变了，改的是判断「是否需要」的那一个函数。
- 默认配置（右 ⌥ 轻按、连按两次）从此不需要任何系统权限，新用户不会再看到授权框或警告。
- 输入监控授权后，系统常会提示「退出并重新打开」。Mochi 照旧在没有权限时轮询状态、拿到后重装监听；若实测仍需重开 app，再在说明文字里注明。
