# Ghost Mode 是透明度、鼠标穿透、隐藏行为绑定在一起的复合状态，不做独立开关的自由组合

> 2026-09-04 更新：本 ADR 的两条具体结论已被 [ADR-0012](0012-ghost-mode-as-pure-invisibility.md) 取代——① Ghost Mode 包含"次级热键召唤工具栏"能力；② 置顶（Pin）与吸附（Snap）与模式无关、两种模式下都可用。此外"鼠标移入即隐藏"被重新分类为可关闭的偏好（且改为移出即恢复），不再算作这个复合状态的组成部分。"Ghost Mode 是绑定的复合状态、不做自由组合开关"这条核心原则仍然成立。保留下文作为历史记录。

最初讨论时曾提议把"透明度""鼠标穿透""自动隐藏"设计成三个独立的原子能力、各自可单独开关，Ghost Mode 只是其中一种常见预设组合。用户最终否决了这个方案：这三者应该被固定捆绑在 Ghost Mode 这一个状态里，不单独拆分成可自由组合的开关；默认热键直接控制 Ghost Mode 整体的开/关。

这个决定源自项目的核心场景——让用户在专注其他应用时，不需要切回这个 Widget 也能控制里面的网页（比如视频播放）。Ghost Mode 作为唯一的"隐身"入口，比三个独立开关的自由组合更符合这个单一目的，减少配置界面的复杂度和用户困惑（不需要考虑"透明度开了但穿透没开"这种不常用的中间态）。

置顶（Pin）和吸附（Snap）明确排除在 Ghost Mode 之外——这两个是窗口摆放的常规便利功能，跟"隐身"无关，Normal Mode 和 Ghost Mode 下都同样可用。

## Consequences

- 应用重启后一律先回到 Normal Mode，不自动恢复 Ghost Mode——避免用户忘记自己开着幽灵模式，一开机就有个看不见、鼠标穿透的窗口在后台运行却毫无感知。
