# Hidden 暂停页面上的全部媒体，取消隐藏不恢复

[ADR-0012](0012-ghost-mode-as-pure-invisibility.md) 给 Hidden（老板键）定的语义是"完全看不见，但页面还在跑——视频不能停"。现在改成：**进入 Hidden 时，暂停页面上所有正在播放的 `<video>` 和 `<audio>`，所有 frame 都算，跨域 iframe 也不例外；取消 Hidden 时什么也不恢复。**

理由来自两个核心使用场景（见 [ADR-0020](0020-video-control-listens-never-intercepts.md)）：上网课时跟着视频动手，以及玩游戏时跟着攻略视频走。在这两个场景里，把窗口藏起来的意思都是"我现在顾不上看"——攻略视频挡住了视线、或者要专心处理眼前的事。等用户回来，视频应该还停在离开的那一刻，而不是已经播过去一大段。

## 为什么取消隐藏不自动恢复

用户回来时，往往要先看清画面、找回上下文，然后才想继续播放。何时继续由用户按视频控制的播放键决定，这只是一颗键的事。自动恢复还要额外记住"哪些视频是被 Hidden 暂停的"，以免把用户手动暂停的视频也播起来——为一个用户并不想要的行为增加记账，不划算。

在 Hidden 状态下直接退出 Ghost Mode，窗口会重新显示出来，但同样不恢复播放，所有"重新显示"的路径行为一致。Hidden 期间用户仍然可以用视频控制手动播放（比如只想听声音）。

## Consequences

- 这个行为不设开关，不管视频控制有没有绑定任何键都生效：它属于 Hidden 本身的语义。
- 页面里视频以外的部分照旧继续运行，所以 Hidden **仍然**必须用 `alphaValue = 0` 实现，不能改用 `orderOut`——ADR-0012 里这条实现约束不变，只是理由从"视频不能停"变成"页面不能停"。
- 不在 DOM 里的媒体（脚本 `new Audio()` 出来、没插进文档的那种）够不着，不会被暂停。
- 在平台层，"暂停全部媒体"复用视频控制注入的脚本：每个 frame 的脚本都带着一个 token 向原生侧报到，原生侧逐个 frame 调用。WebKit 没有公开的方法列出一个 web view 的所有 frame，只能靠这种报到。
